## A1 — P1: обход доступа к посещаемости через имя

Код: backend/services/attendanceService.js:97–107;
backend/routes/users.js:114–178.

Доступ предоставляется по teacher_id ИЛИ совпадению имени/email. Имя можно
изменить в собственном профиле. Воспроизведено: преподаватель получает 403
при открытии чужого занятия, переименовывается в назначенного преподавателя,
получает 200 и успешно сохраняет чужую посещаемость через POST /api/attendance.

Исправление: авторизация по неизменяемому ID. Для занятий без course_id нужна
явная связь с преподавателем. Одна политика для списка, просмотра, записи,
аналитики и истории. Тестировать переименование и переназначение курса.

## A2 — P1: студент редактирует административные поля

Код: backend/routes/users.js:114–178 и :450–530.

Собственный профиль позволяет менять group_name, subgroup_name, study_status,
balance_info, grant_type и другие учебные поля. PUT /:id тоже разрешает
изменять собственную запись. Воспроизведено: группа AUDIT-OTHER-GROUP,
статус graduated, баланс 0 сохранены с ответом 200. Это не финансовая операция,
но нарушение целостности профиля. Группа влияет на расписание и объявления.

Исправление: отделить личные контактные поля от административных и защитить
оба маршрута. Проверять неизменность записей при запрещённых изменениях.

## A3 — P1: оценка сохраняется при сбое аудита

Код: backend/routes/grades.js:32–79; backend/utils/auditTrail.js:47.

Оценка и история записываются без общей транзакции. На тестовом экземпляре
искусственно вызван отказ записи grade_audit_log: API вернул 500, но оценка 77
осталась в grades; строк аудита было 0. Ошибка ответа не означает откат.

Исправление: транзакция оценки и обеих записей аудита. На PostgreSQL запросы
транзакции должны выполняться на одном подключении. Аналогично проверить
массовую посещаемость и замену exam_students: там тоже несколько изменений
без атомарности. Добавить тесты отказов и конкурентных изменений.

## A4 — P2: задания чужих курсов доступны студенту

Код: backend/routes/assignments.js:19–22;
backend/services/assignmentService.js:58–65.

listAssignments не принимает пользователя и возвращает все задания.
Воспроизведено: GET /api/assignments возвращает студенту задание курса,
на который он не записан.

Исправление: фильтр по course_enrollments для студента, назначенным курсам
для преподавателя; общий доступ для администратора. Определить правила
заданий без course_id. Фильтрация должна быть на сервере.

## A5 — P2: смена пароля не отзывает старые сессии

Код: backend/routes/auth.js:214; backend/middleware/auth.js:31–44.

Воспроизведено: после смены пароля старый JWT получает 200 на GET /api/auth/me.
Проверяются подпись и активность аккаунта, но нет версии сессии/отзыва.
При компрометации токена смена пароля не прекращает доступ.

Исправление: session_version либо серверные сессии. При смене пароля отзывать
предыдущие сессии; текущую при необходимости перевыпускать. Logout сейчас
очищает cookie; политику серверного отзыва также нужно определить.

## Дополнительные выводы по коду

### A6 — P2: общая история посещаемости доступна преподавателю

backend/services/attendanceService.js:796–820 проверяет принадлежность
studentId только для студента. Преподавателю доступны записи любого студента
по всем предметам. Отдельный HTTP-прогон этого маршрута не выполнялся.
Нужно определить и применить область доступа преподавателя в SELECT.

### A7 — P2: ручной deploy gate пропускает PostgreSQL-тест

.github/workflows/render-deploy-gate.yml запускает npm test без
TEST_DATABASE_URL; backend/tests/postgres-smoke.test.js в таком случае
пропускается. В обычном CI PostgreSQL job есть, но ручной gate его не включает.
Добавить PostgreSQL service и обязательный job либо общий reusable workflow.
