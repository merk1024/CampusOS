# Демо CampusOS на ноутбуке и телефоне

Это одноразовый стенд, а не production: отдельная временная SQLite-база,
готовые учебные данные и новый случайный пароль при каждом запуске.
Рабочие `.env`, PostgreSQL и Render не изменяются. Интеграций PMS/OCS нет.

## Первый запуск

Нужен Node.js версии, совместимой с проектом (локально проверено на 22.19.0), и установленные
зависимости. Из корня проекта:

```text
npm --prefix backend ci
npm --prefix frontend ci
```

Если зависимости уже установлены, повторять установку не нужно.

## Только на ноутбуке

```text
npm run demo:local
```

Откройте адрес из строки `Open:`. По умолчанию: `http://127.0.0.1:4175`.

## С телефона в той же Wi-Fi-сети

```text
npm run demo:phone
```

Откройте на телефоне адрес из строки `Open:`, например `http://192.168.1.20:4175`.
Не используйте `localhost` на телефоне: это адрес самого телефона, не ноутбука.
При нескольких сетевых адаптерах команда покажет доступные частные IPv4-адреса.
Выберите IPv4 именно Wi-Fi/Ethernet-интерфейса вашей общей сети:

```text
npm run demo:phone -- --host=192.168.1.20
```

Подставьте фактический адрес ноутбука. Публичные адреса и `0.0.0.0` не принимаются.
Если порт занят, используйте `--port=4176`. Скрипт не завершает чужие процессы.

При первом запуске сборка занимает некоторое время. Ждите строки `DEMO_READY`:
до неё стенд ещё не готов. Адрес и временный пароль находятся в этой строке;
пароль не записывается в Git или исходный `.env`.

## Демо-учётные записи

| Роль | Логин |
| --- | --- |
| Владелец | `owner@campusos.test` |
| Администратор | `admin@alatoo.edu.kg` |
| Преподаватель | `teacher@alatoo.edu.kg` |
| Студент | `240141052` |

У всех демонстрационных пользователей пароль из текущей строки `DEMO_READY`.
Это только демо-пароль; не используйте его в настоящих аккаунтах.
Можно проверить расписание, курсы, экзамены, оценки и центр безопасности.

## Если телефон не подключается

- Ноутбук должен оставаться включённым, а команда — работать.
- Оба устройства должны быть в одной доверенной локальной сети.
- Гостевой Wi-Fi и изоляция клиентов роутера могут запрещать связь устройств.
- VPN/мобильный интернет могут направлять запросы в другую сеть.
- Если Windows показывает запрос firewall, разрешайте Node только в доверенной
  частной сети. Не отключайте firewall целиком. Скрипт сам его правила не меняет.

## Остановка и границы безопасности

Нажмите Ctrl+C в терминале запуска. При штатной остановке временная база, сборка
и ключи удаляются. При аварийном завершении временный каталог может остаться в
системном TEMP; следующий запуск всё равно создаёт новый, не использует старую БД.
Все изменения демо сбрасываются: для важных данных нужен другой, постоянный стенд.

API слушает только `127.0.0.1` на случайном порте. Телефон получает сайт и API через
один LAN-адрес; исходники, `.env`, Vite dev-server и PostgreSQL в сеть не публикуются.
Обычные серверные проверки прав и Origin остаются включены.

Это HTTP без шифрования транспорта. Используйте только вымышленные данные и
доверенный Wi-Fi, без публичных туннелей, проброса портов или внешнего доступа.
Нельзя проверять здесь реальные пароли, production Secure-cookie или гарантии HTTPS.
MFA можно исследовать на одноразовых аккаунтах, но provisioning/recovery-коды
на HTTP-стенде нельзя считать защищёнными от наблюдателя локальной сети.
