# PostgreSQL для CampusOS

Основная локальная БД — PostgreSQL 17 в Docker. Данные хранятся в томе
`campusos_postgres_data`, порт доступен только на `127.0.0.1`.

## Первый запуск

Нужны Node.js 24 с npm и запущенный Docker Desktop. Из корня проекта:

```powershell
npm --prefix backend ci
npm run db:setup
npm run db:up
npm run db:init
npm run db:check
npm run dev:backend
```

`db:setup` создаёт отсутствующий `backend/.env` со случайными паролями БД,
bootstrap-аккаунта и JWT-секретом. Существующий файл не перезаписывается.
Если файл уже подготовлен, пропустите эту команду.

Параметры подключения для pgAdmin / DBeaver:
- Host: `127.0.0.1`
- Port: `5432`
- Database: `campusos`
- User: `campusos`
- Password: значение `DB_PASSWORD` из `backend/.env`

Файл `backend/.env` исключён из Git. Не публикуйте его.
`PGSSLMODE=disable` предназначен для локального контейнера.

## Существующая конфигурация

Установите `DB_CLIENT=postgres`. Можно задать `DATABASE_URL` либо отдельные
`DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`.
При наличии `DATABASE_URL` приложение использует его; он должен соответствовать
параметрам контейнера. Если порт 5432 занят, измените `DB_PORT` и порт в URL.

Пароль и имя БД из Compose применяются при первом создании тома.
Изменение .env само по себе не меняет пароль уже созданного пользователя PostgreSQL.

## Схема и данные

`db:init` применяет версионированные миграции к выбранной БД и сохраняет данные.
`db:check` читает список таблиц и число применённых миграций.
Backend тоже применяет миграции перед стартом.

Для учебных данных задайте `SEED_ADMIN_PASSWORD`, `SEED_TEACHER_PASSWORD`,
`SEED_STUDENT_PASSWORD` в .env, затем выполните `npm run seed:demo`.
Bootstrap-пароль уже создаётся командой настройки.
Seed создаёт или обновляет демонстрационные записи; запускайте его только в учебной БД.

Файл SQLite автоматически не переносится. Если в нём есть нужные данные,
потребуется отдельный экспорт и проверяемый импорт перед переключением.
SQLite остаётся доступным для существующих тестов через `DB_CLIENT=sqlite`.

## Остановка и повторный запуск

```powershell
npm run db:stop
npm run db:up
```

Остановка сохраняет том и данные. Не используйте `docker compose down -v`
для обычной остановки: эта команда удаляет том.

## Проверки

```powershell
npm run test:backend
```

Дополнительная интеграционная проверка PostgreSQL запускается при наличии
`TEST_DATABASE_URL`, указывающего на отдельную пустую тестовую БД.
Она создаёт учебные записи и не должна запускаться на рабочей БД.
CI создаёт отдельную БД для этой проверки.
